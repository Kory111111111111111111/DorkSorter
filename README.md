# DorkSorter

A searchable, filterable index of 90,000+ Google dorks — plus a comprehensive
**Dork Builder** for composing new ones. Ingests the raw dork `.txt`
collection, deduplicates, auto-categorizes by source file and content
heuristics, tags each query with its technique, and assigns a risk level
(critical / high / medium / low / info).

## Stack

- Next.js 16 (App Router) + TypeScript
- Tailwind CSS v4 + shadcn/ui (Base UI primitives)
- Single static dataset (`src/data/dorks.json`). The build writes a compact
  index to `public/dorks.json` (dictionary of labels, one short row per dork).
  The browser downloads that once and runs search, filter, sort, and pagination
  locally so the site can be hosted on GitHub Pages

## Features

### Browse

- Live search (debounced), filter by category / risk level / tag. Shift-click
  categories in the sidebar to select more than one
- Sort by risk, A–Z, Z–A, or category
- Copy any dork or open it directly in Google search
- Click any tag chip to filter the whole corpus by that tag
- **Open in Builder** (wand icon) on any dork card to pull it into the Dork
  Builder for tweaking
- Dark theme by default (light mode available via the header toggle)
- Global category counts + per-result risk counts in the sidebar

### Dork Builder

Compose Google dorks from a library of 25+ operators (site, inurl, intitle,
intext, inanchor, filetype/ext, AROUND(n), dates, and legacy/discontinued
operators) with AND / OR / NOT logic:

- **Live query preview** with syntax coloring, plus Copy / Open in Google /
  Clear actions
- **Corpus-mined value suggestions** — the value inputs pull the most common
  file types, domains, URL/title/body terms, and quoted phrases straight from
  the dork corpus
- **Variations** — separate a value with `|` (or newlines) and generate every
  combination as a batch, with copy-all
- **Heuristic risk estimation** — every assembled query gets a risk badge
  (critical → info) with the specific operators/terms that drove it
- **15 curated templates** (open directories, .env & secrets, exposed .git,
  database dumps, admin panels, cloud buckets, camera feeds, …) loadable from
  the sidebar
- **Round-trip parsing** — paste any existing dork to load it as editable rows;
  parse and build normalize aliases (`ext:` → `filetype:`) and preserve
  quoted phrases and exclusions

## Data

The dataset is generated by the ingestion script. It reads the local
Proviesec corpus (`DORKS_DIR`, default `C:/Users/koryi/Desktop/google-dorks`)
and the cloned lists under `sources/` (BullsEye0, TUXCMD, TakSec, sushiwushi,
Ishanoshada/GDorks, and the Exploit-DB GHDB cheatsheet from readloud).

```bash
# Defaults to C:/Users/koryi/Desktop/google-dorks; override with DORKS_DIR
DORKS_DIR="C:/path/to/dorks" npx tsx scripts/ingest-dorks.ts
```

This rewrites `src/data/dorks.json`. The same query is stored once, matched
case-insensitively (`article.php?ID=` and `article.php?id=` collapse). A
topic file wins over a bulk dump, which wins over `all-google-dorks.txt`.
Carding lists, shopping dumps, and the GDorks `Dorks(1M)` folder are not
imported. Each kept query gets auto-detected tags and a heuristic risk level.

## Project layout

```
src/app/          Next.js app router and global styles
src/components/   Sidebar, dork card, dork builder, shadcn/ui primitives
src/hooks/        useDorks — filter state and debounced search over the corpus
src/lib/          risk constants, dork operators, builder core, templates,
                  corpus loading, query, and suggestion mining
src/data/         generated dorks.json (do not hand-edit; regenerate)
scripts/          ingest-dorks.ts — corpus ingestion pipeline
                  stage-public-data.mjs — copies the corpus into public/ for
                  the static export
.github/workflows pages.yml — builds and deploys to GitHub Pages
```

## GitHub Pages

Pushes to `dork-builder`, and manual runs of **Deploy to GitHub Pages**, publish
a static export. One-time setup in the repo: **Settings → Pages → Build and
deployment → Source: GitHub Actions**.

The site is served from `https://<user>.github.io/DorkSorter/`. The workflow
sets `BASE_PATH` from GitHub’s Pages configuration so assets resolve under that
subpath. A local `npm run build` leaves the base path empty and writes `out/`.
